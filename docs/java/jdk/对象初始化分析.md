# JVM 对象初始化 — 内置类型 vs 普通对象

> 上次修改：2026-06-06 15:30

## 1. 概述

JVM 对象的初始化发生在两个截然不同的层面:

1. **Java 层对象实例化**: 通过 `new` 指令或 `Unsafe.allocateInstance()` 在 Java **堆**中创建对象实例 (oop)
2. **JVM 内部元数据初始化**: 在 Metaspace 中创建 Klass 元数据, 以及在堆中创建预分配的系统对象

本文重点关注 JVM 启动过程中的对象初始化。

## 3. 对象的内存布局

所有 Java 对象 (oop) 在堆中的布局:

### 3.1 普通对象 (instanceOop)

```
┌──────────────────┐  ← mem
│     markWord     │  8/4 bytes (64/32-bit)
├──────────────────┤  ← oopDesc::base_offset_in_bytes()
│   Klass* (压缩)  │  4 bytes (压缩) 或 8 bytes (非压缩)
├──────────────────┤
│   [klass_gap]    │  4 bytes padding (仅压缩Klass时存在, 对齐)
├──────────────────┤
│    字段 0        │
│    字段 1        │  ... 实例字段
│    ...           │
└──────────────────┘  ← mem + size
```

**源文件**: `src/hotspot/share/oops/oop.hpp` (class oopDesc)

```cpp
class oopDesc {
  volatile markWord _mark;       // 标记字 (锁状态, GC信息, hash)
  union _metadata {
    Klass*      _klass;          // 非压缩: 8 bytes
    narrowKlass _compressed_klass; // 压缩: 4 bytes
  } _metadata;
};
```

### 3.2 数组对象 (arrayOop)

```
┌──────────────────┐  ← mem
│     markWord     │  8/4 bytes
├──────────────────┤
│   Klass* (压缩)  │  4/8 bytes
├──────────────────┤
│   [klass_gap]    │  4 bytes (压缩Klass时)
├──────────────────┤  ← arrayOopDesc::length_offset_in_bytes()
│   数组长度(int)  │  4 bytes
├──────────────────┤  ← arrayOopDesc::base_offset_in_bytes(type)
│   元素 0         │
│   元素 1         │
│   ...            │
└──────────────────┘
```

**关键**: 数组的 length 字段紧跟在 klass 之后。

### 3.3 Class 镜像对象 (InstanceMirrorKlass)

```
┌──────────────────┐  ← mem
│     markWord     │
├──────────────────┤
│   Klass* (指向 Class_klass) │
├──────────────────┤
│   oop_size       │  本镜像的实际大小 (关键!)
├──────────────────┤
│   普通实例字段    │  来自 Class 类本身的字段
│   ...            │
├──────────────────┤  ← _offset_of_static_fields
│   静态字段 0      │  ★ 所属类的 static 字段存储在此!
│   静态字段 1      │
│   ...            │
└──────────────────┘
```

**源文件**: `src/hotspot/share/oops/instanceMirrorKlass.hpp`

## 4. 基本类型镜像 (Primitive Type Mirrors)

### 4.1 触发时机

在 `Universe::genesis()` → `vmClasses::resolve_all()` 中, 当 `java.lang.Class` 类被加载后:

### 4.2 调用链

```
Universe::genesis()
  → SystemDictionary::initialize()
    → vmClasses::resolve_all()
      → resolve_through(Class_klass)
        → SystemDictionary::resolve_or_fail("java/lang/Class")
      → java_lang_Class::compute_offsets()
      → Universe::initialize_basic_type_mirrors()
        → java_lang_Class::create_basic_type_mirror("int", T_INT)
        → java_lang_Class::create_basic_type_mirror("float", T_FLOAT)
        → ... (T_BOOLEAN to T_VOID, 共 10 种)
```

### 4.3 具体创建过程

```cpp
oop java_lang_Class::create_basic_type_mirror(const char* basic_type_name,
                                              BasicType type, TRAPS) {
  // 1. 通过 InstanceMirrorKlass 分配 oop, 传入 k=null 表示基本类型!
  oop java_class = InstanceMirrorKlass::cast(vmClasses::Class_klass())
                     ->allocate_instance(nullptr, CHECK_NULL);
  //    ★ klass 字段为 null: 这是基本类型镜像的标志

  if (type != T_VOID) {
    // 2. 设置 array_klass 字段指向对应的 TypeArrayKlass
    //    比如 int.class -> int[] TypeArrayKlass
    Klass* aklass = Universe::typeArrayKlass(type);
    release_set_array_klass(java_class, aklass);
  }
  // void 的 array_klass 保持为 null (没有 void[] 类型)

  // 3. 设置修饰符: public abstract final
  set_modifiers(java_class, JVM_ACC_ABSTRACT | JVM_ACC_FINAL | JVM_ACC_PUBLIC);
  set_is_primitive(java_class);   // 设置基本类型标志
  return java_class;
}
```

**源文件**: `src/hotspot/share/classfile/javaClasses.cpp` line 1382

### 4.4 和普通 Class 镜像的三大区别

| 特性 | 基本类型镜像 (int.class) | 普通类镜像 (String.class) |
|------|--------------------------|---------------------------|
| klass 字段 | **null** | 指向对应的 InstanceKlass |
| 创建方式 | `create_basic_type_mirror()` | `create_mirror()` |
| array_klass 字段 | 指向 TypeArrayKlass (void 除外) | 指向 ObjArrayKlass (或 null) |
| 静态字段 | 无 | 有可能 (存储在镜像末尾) |
| is_primitive() | true | false |
| 存储在 | `Universe::_basic_type_mirrors[]` | 每个 Klass 的 _java_mirror 字段 |

## 5. 基本类型数组 (TypeArrayKlass / typeArrayOop)

### 5.1 创建时机

在 `Universe::genesis()` 中, **早于** 任何 Java 类加载:

```
Universe::genesis()
  → compute_base_vtable_size()              // 必须先计算 vtable 大小
  → for (i = T_BOOLEAN; i <= T_LONG; i++)
      → TypeArrayKlass::create_klass(type)  // 创建 8 个 TypeArrayKlass
  → initialize_basic_type_klass(每个)       // 初始化超类和 vtable
```

### 5.2 TypeArrayKlass 的 Klass 类别和超类

```
Object (InstanceKlass)
  └─ Abstract interface (for arrays)
       ├─ Cloneable (interface)
       ├─ Serializable (interface)
       └─ ArrayKlass (abstract)
            └─ TypeArrayKlass
                 ├─ boolean[] Klass
                 ├─ byte[]    Klass
                 ├─ char[]    Klass
                 ├─ short[]   Klass
                 ├─ int[]     Klass
                 ├─ long[]    Klass
                 ├─ float[]   Klass
                 └─ double[]  Klass
```

## 6. 普通对象的初始化 (InstanceKlass / instanceOop)

### 6.1 Klass 元数据加载

与基本类型数组不同，普通 Java 类的元数据通过类加载器加载:

```cpp
// vmClasses::resolve_all() 中:
SystemDictionary::resolve_or_fail("java/lang/Object");
SystemDictionary::resolve_or_fail("java/lang/String");
// ... 所有 ~100 个预定义类依次加载
```

加载流程:
```
SystemDictionary::resolve_or_fail()
  → ClassFileParser::parseClassFile()        // 解析 class 文件字节码
  → InstanceKlass 在 Metaspace 中分配
  → 常量池解析, 方法/字段元数据创建
  → create_mirror()                          // 创建 java.lang.Class 镜像
```

### 6.2 三个分配器对比

| 分配器 | allocate() 调用 | initialize() 特殊处理 |
|--------|----------------|----------------------|
| `ObjAllocator` | `obj_allocate` | `mem_clear` + `finish` |
| `ObjArrayAllocator` | `array_allocate` | `set_length` + `finish` (先设长度) |
| `ClassAllocator` | `class_allocate` | `set_oop_size` + `finish` (先设大小) |

**源文件**: `src/hotspot/share/gc/shared/memAllocator.cpp`

### 6.3 TypeArray vs ObjArray 的核心区别

| 特性 | TypeArray (int[]) | ObjArray (Object[]) |
|------|-------------------|---------------------|
| Klass 类型 | TypeArrayKlass | ObjArrayKlass |
| 创建方式 | 启动时全量创建 | 按需加载 |
| 元素 | 标量值 | oop 引用 (GC 跟踪) |
| GC 扫描 | 不需要 (无引用) | 需要 (扫描每个元素) |
| 超类 | Object | Object / 元素类型的数组超类 |
| 接口 | Cloneable + Serializable | Cloneable + Serializable |

## 7. String 对象的初始化

String 的初始化涉及两个独立层面: **String 类本身的元数据初始化** 和 **String 实例/字面量的创建**。

### 7.1 String 类初始化

在 `initialize_java_lang_classes()` 中, **第一个**被初始化的类:

```cpp
void Threads::initialize_java_lang_classes(JavaThread* main_thread, TRAPS) {
  initialize_class(vmSymbols::java_lang_String(), CHECK);
  // → java.lang.String 的 <clinit> 被调用
  // → 设置 CompactStrings 标志
  java_lang_String::set_compact_strings(CompactStrings);
  // ...
}
```

### 7.2 String 对象创建路径

```cpp
Handle java_lang_String::basic_create(int length, bool is_latin1, TRAPS) {
  // 1. 在堆上创建空 String 对象
  oop obj = vmClasses::String_klass()->allocate_instance(CHECK_NH);
  Handle h_obj(THREAD, obj);

  // 2. 创建 byte[] 作为 value 字段的后备数组
  int arr_length = is_latin1 ? length : length << 1;
  typeArrayOop buffer = oopFactory::new_byteArray(arr_length, CHECK_NH);

  // 3. 设置 String 的内部字段
  obj = h_obj();
  set_value(obj, buffer);              // value 字段 → byte[]
  set_coder(obj, is_latin1 ? CODER_LATIN1 : CODER_UTF16);  // coder 字段
  return h_obj;
}
```

## 8. 预分配异常对象

在 `universe_post_init()` 中:

```cpp
bool universe_post_init() {
  Universe::_fully_initialized = true;

  // 1. 空的 Class[] 数组 (用于反射)
  objArrayOop empty = oopFactory::new_objArray(vmClasses::Class_klass(), 0);
  Universe::_the_empty_class_array = OopHandle(vm_global(), empty);

  // 2. 6 种 OOM 错误 + 消息
  Universe::create_preallocated_out_of_memory_errors(CHECK_false);

  // 3. 编译器使用的预分配异常
  _null_ptr_exception.init_if_empty(NPE);
  _arithmetic_exception.init_if_empty(AE);
  _array_index_out_of_bounds_exception.init_if_empty(AIOOB);
  _array_store_exception.init_if_empty(ASE);
  _class_cast_exception.init_if_empty(CCE);
}
```

### 三维评估：预分配异常

#### 这样实现的好处
- **编译代码可直接引用**：C2 编译器生成的代码可以直接返回预分配异常对象，无需调用 `new`
- **减少分配开销**：异常对象在启动时一次分配，运行时 OOM 场景下无需再次分配
- **OopHandle 保护**：通过 `_vm_global` OopStorage 防止 GC 回收

#### 是否有更好的方案
- **延迟分配**：首次需要时再创建异常对象，减少启动内存占用
- **每个异常类型仅一个实例**：当前方案已如此，但异常栈轨迹可能不准确（填充栈轨迹需 `fillInStackTrace()`）
- **完全 Java 侧分配**：不预分配，完全依赖 Java 的 `new` 操作

#### 不这么实现的问题
- **预分配浪费**：如果 JVM 从未发生某种异常，预分配的对象浪费堆空间
- **多线程问题**：多个线程同时抛出 NPE 时共享同一预分配对象，需要 `fillInStackTrace()` 每次创建新栈轨迹
- **OOM 场景悖论**：在 OOM 时不能再分配新对象，预分配正是为此设计

## 9. 六种对象初始化路径对比总结

| # | 对象类型 | 元数据 (Klass) 位置 | 实例 (oop) 位置 | 创建时机 | 创建机制 | 特殊点 |
|---|---------|-------------------|----------------|---------|---------|-------|
| 1 | **基本类型镜像** (int.class) | 无 klass 指针! | Java 堆 (InstanceMirrorKlass) | genesis 中 | create_basic_type_mirror | klass=null, is_primitive=true |
| 2 | **TypeArray (int[])** | Metaspace (TypeArrayKlass) | Java 堆 (typeArrayOop) | genesis 中预创建8种 | TypeArrayKlass::create_klass | 静态已知, 无引用扫描 |
| 3 | **ObjArray (Object[])** | Metaspace (ObjArrayKlass) | Java 堆 (objArrayOop) | 按需加载 | ObjArrayKlass::allocate_objArray_klass | 维度链, GC 跟踪引用 |
| 4 | **普通对象** (String, Thread) | Metaspace (InstanceKlass) | Java 堆 (instanceOop) | 类加载时 | InstanceKlass::allocate_instance | 固定大小, 构造函数调用 |
| 5 | **Class 镜像** (String.class) | Metaspace (InstanceKlass) | Java 堆 (InstanceMirrorKlass) | 类加载时 | create_mirror → class_allocate | 变长 (含静态字段), 自描述大小 |
| 6 | **预分配异常** (OOM, NPE) | Metaspace (InstanceKlass) | Java 堆 + OopHandle | universe_post_init | BuiltinException::init_if_empty | 永不被 GC, 编译器直接引用 |

### 关键区别要点

1. **Metaspace vs Heap**: Klass 元数据始终在 Metaspace; 对象实例 (oop) 始终在 Java 堆
2. **固定大小 vs 变长**: 普通对象固定大小；Class 镜像变长（含静态字段）；数组变长（由长度决定）
3. **创建顺序**: TypeArrayKlass 最先 → Object → String → Class → SystemDictionary → 所有预定义类 → 基本类型镜像 → 预分配异常
4. **引用跟踪**: TypeArray 元素不是 oop, GC 不需要扫描; ObjArray 元素是 oop, GC 需要跟踪
5. **Class 镜像的无 klass 特例**: 基本类型镜像的 klass 字段为 null，这是 JVM 区分基本类型与引用类型的核心机制
